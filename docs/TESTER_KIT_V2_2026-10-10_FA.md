# بستهٔ تست اقتصاد v2

این ابزار برای حساب‌های مشخصی است که مالک صریحاً برای تست انتخاب می‌کند؛ حساب تازه ایجاد نمی‌کند. در درخواست ۱۰ اکتبر، سه حساب `@mh_nmd`، `@Sisikarbalad` و `@Macpishe` پیدا شدند. `@SuperPedaret` موجود نبود و مالک ادامهٔ کار با همان سه حساب را خواست.

## رفتار بسته

- پرچم `legacy` فقط برای حساب‌های انتخاب‌شده صفر می‌شود تا جوایز Level آینده را بگیرند.
- Level، XP، Score، تاریخچه، دک‌ها، فرم فعال کارت موجود و ظرفیت قبلی قلب/دک حفظ می‌شوند. جایزهٔ عقب‌افتادهٔ Level پرداخت نمی‌شود.
- برای هر شخصیت رسمی، حداقل ۹ Normal، سه Epic و یک Legend موجود می‌شود؛ موجودی بالاتر کم نمی‌شود. کاتالوگ فعلی ۱۰۱ شخصیت و ۳۰۳ ترکیب شخصیت/فرم دارد.
- هرکدام از ۱۰ ابیلیتی مصرفی موجود، حداقل ۲۰ بار قابل استفاده می‌شود.
- Coin حداقل ۲۰٬۰۰۰؛ کارت ارتقا حداقل ۲۰؛ Silver Ticket حداقل ۳۰؛ Silver Claim رایگان حداقل سه. قلب‌ها تا ظرفیت موجود پر می‌شوند.
- زمان Daily Claim و رسید مأموریت/خرید/ارتقا پاک نمی‌شود؛ محدودیت روزانه و شرایط Levelِ Modeها برقرارند. بستهٔ تست، نبرد تمرینی را پاداش‌دار یا Friendly/Custom را فعال نمی‌کند.
- دریافت مصنوعی این منابع، XP یا Score ندارد و مأموریت بازی/Claim/Upgrade را خودکار تکمیل نمی‌کند. این بسته برای آزمون عملکرد است؛ سنجش زمان طبیعی کسب Coin/کارت باید روی حساب تازهٔ بدون هدیه انجام شود.

## اجرا توسط مالک

ابزار `scripts/provision_economy_testers.py` پیش‌نمایش روی کپی خصوصی و اجرای زنده با بکاپ تازه دارد. باید هر username با آیدی عددیِ بررسی‌شدهٔ همان حساب وارد شود؛ اختلاف هویت یا مسابقهٔ فعال کل عملیات را رد می‌کند. تغییر ظرفیت قبلی بالاتر از سقف جدید به بررسی جدا نیاز دارد.

```bash
python scripts/provision_economy_testers.py \
  --database /path/to/existing-game.db \
  --account VERIFIED_USERNAME:VERIFIED_NUMERIC_ID \
  --actor owner-reviewed --batch UNIQUE_BATCH \
  --preview-copy /path/to/new-private-preview.db
```

پس از بازبینی، همان ورودی‌ها با `--apply --backup /path/to/new-private-backup.db` جایگزین preview شوند. اجرای زندهٔ مالک زیر `/opt/telbattle/deploy.lock` و با توقف موقت سه سرویس انجام شود. همکارِ شاخهٔ `collab/` اجازهٔ استفاده از دیتابیس تولید یا SSH مالک را ندارد.

تمام عملیات تراکنشی و رسیددار است. `batch` یکسان، رسید قبلی را برمی‌گرداند و منابع مصرف‌شده را دوباره شارژ نمی‌کند؛ همان batch با حساب/بستهٔ متفاوت رد می‌شود. برای شارژ جدید، مالک باید صریحاً batch تازه انتخاب کند. رویداد اعطا و مقدار افزوده‌شده در `reward_ledger` و audit ادمین ثبت می‌شوند. تمام رکوردهای غیرمرتبط و قواعد جهانی پیش/پس مقایسه می‌شوند؛ SQLite و FK کنترل می‌شوند. هیچ schema یا گزینهٔ جهانی جدیدی ایجاد نمی‌شود.

هشت آزمون، حفظ آمار/فرم/موجودی بالاتر، جوایز Level آینده، حساب عادی، retry پس از مصرف، هویت اشتباه، مسابقهٔ فعال، خاموش‌بودن اقتصاد، ظرفیت ناسازگار و rollback خطای میانی را پوشش می‌دهند:

```bash
python -m pytest -q tests/test_tester_provision.py
```

وضعیت اجرای واقعی و تعداد حساب‌های قدیمی در [وضعیت انتشار](DEPLOYMENT_STATUS_2026-10-10_FA.md) ثبت می‌شود. این ابزارِ مالک خارج از بستهٔ runtime است و افزودن آن به GitHub به معنای تغییر نسخهٔ بات/API نیست.

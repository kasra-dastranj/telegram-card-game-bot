# انتشار تجربهٔ بازیکن، ورود اولیه و فروش ابیلیتی — ۱۸ اکتبر ۲۰۲۶

[PR شمارهٔ ۷](https://github.com/kasra-dastranj/telegram-card-game-bot/pull/7) پس از بررسی کد و تست، توسط مالک تأیید و ادغام شد. نسخهٔ محلی با main هماهنگ است و artifact موفق CI همان commit ادغام‌شده روی VPS منتشر شد. نسخهٔ قبلی، [انتشار تصاویر نبرد و Claim](RELEASE_20261018_BATTLE_VISUALS_CLAIMS_EASY.md) بود.

## رفتار منتشرشده

- **ورود اولیه:** نخستین /start خصوصی، پس از تأیید عضویت، خوشامد و دکمهٔ «دریافت کارت‌های اولیه» را نشان می‌دهد. سه کارت Normal و دک آغازین با یک تراکنش و رسید پایدار اعطا می‌شوند؛ ربات سه استیکر همان فرم را می‌فرستد و راهنمای /claim می‌دهد. Daily Claim خودکار اجرا نمی‌شود.
- **حفظ منابع شروع:** رسید Telegram و Mini App مشترک است؛ کلیک هم‌زمان یا تکراری، دریافت از مینی‌اپ و فروش/مصرف کارت‌ها، بستهٔ دوباره نمی‌دهد. ارسال ناقص استیکر از وضعیت ثبت‌شده ادامه پیدا می‌کند و خطای رسانه اعطای کارت را تکرار نمی‌کند. پیشنهاد شروعِ ثبت‌شده با گرفتن Daily Claim از دست نمی‌رود. سیاست حساب‌های قدیمی V2 حفظ شده است.
- **نمایش Easy:** سؤال در پیام موقت ریپلای‌شدهٔ همان راند قرار دارد؛ پنل اصلی امتیاز و نتیجهٔ راند را نشان می‌دهد. نام آماده‌ها، مدال و رتبهٔ مشترک مسابقه‌ای نمایش داده می‌شوند. سؤال، تایمر، انتخاب و تسویه از منطق قبلی استفاده می‌کنند.
- **پروفایل و برد Easy:** بازیکن از پروفایل، یک شخصیت/فرم موجود و شعار تا ۱۲۰ نویسه انتخاب می‌کند. تنها نفر اول، استیکر همان فرم و شعار برد را در گروه می‌فرستد؛ تساوی رتبهٔ اول فقط جدول نتیجه دارد. مالکیت/دسترسی هنگام انتخاب و ارسال دوباره کنترل می‌شود؛ فرم دیگری جای کارت ناموجود قرار نمی‌گیرد.
- **شاپ خصوصی:** ورود شاپ و callbackهای قدیمی خرید، تأیید، تبدیل، اسکین و عملیات شخصی در گروه پیش از عملیات مالی متوقف می‌شوند و راهنمای پیوی می‌دهند.
- **خرید ابیلیتی:** بخش «Ability cards · خرید و موجودی» تعداد هر ده ابیلیتی، حتی صفرها، و خرید یک مصرف را نشان می‌دهد. خرید از همان quote، کنترل مالکیت/انقضا/قیمت، تراکنش و رسید قبلی عبور می‌کند؛ موجودی مشترک بازی‌ها استفاده می‌شود. قفل ویژگی همچنان فقط برای Quick است.
- **کارت، فروش و مأموریت:** بازکردن اطلاعات کارت، استیکر فرم فعال همان کارت را می‌فرستد؛ علاقه‌مندی آن را تکرار نمی‌کند. فروش تازه و موفق پیام جداگانهٔ 💰 دارد؛ replay یا خطا آن را ایجاد نمی‌کند. مأموریت‌ها از شاپ به پروفایل منتقل شده‌اند و وضعیت، توضیح، نوار پیشرفت، پاداش و صفحه‌بندی پنج‌تایی دارند.
- **لول‌آپ:** اعلان خصوصی از صف پایدار، پاداش‌های واقعاً ثبت‌شده و حالت تازهٔ بازشده را اعلام می‌کند. سقف ظرفیت قلب و freeze جوایز حساب قدیمی لحاظ شده‌اند؛ گذشته backfill نمی‌شود و ارسال اعلان هیچ پاداشی پرداخت نمی‌کند. job هر ۱۵ ثانیه حداکثر ده اعلان را بررسی می‌کند؛ شکست ارسال، تلاش بعدی را ۳۰ دقیقه عقب می‌اندازد.
- **متن‌ها:** پیام‌های دعوت، خطا، موجودی، Claim، ارتقا و Risk خواناتر شدند. نام واقعی بازیکن در Risk، جداسازی جهت فارسی/لاتین، علامت XP و Score، کسرها و escape نام‌های Markdown کنترل شده‌اند. ID، URL، callback و دادهٔ اصلی با قالب نمایشی جایگزین نمی‌شوند.

## نتیجهٔ بررسی

- **محلی: ۲۰۸ تست موفق در Python 3.12، مدت ۹۴٫۰۷ ثانیه.** پوشش: Easy presentation، onboarding، personal economy، player messages و progression v2؛ SQLite موقت و Telegram mock. این اجرای محلی، تمام تست‌های مخزن نیست.
- **CI نهایی: در هر دو Python 3.11 و 3.9.25، تعداد ۹۱۰ موفق و ۱ skipped.** JUnitهای همان run دانلود و شمارش شدند: هر کدام ۹۱۱ مورد با صفر failure و صفر error. تست زندهٔ تلگرام عمداً اجرا نشده است.
- ساخت فرانت‌اند، syntax JavaScript پنل، بسته‌بندی و CI gate موفق‌اند. workflow، helper انتشار، migrations و requirements تغییر نکرده‌اند.
- manifest/hash تمام **۱۳۴ فایل runtime** تأیید شد؛ هر **۱۳۰ فایل source** با blob canonical همان commit Git تطبیق دارد. چهار فایل دیگر محصول build CI هستند.
- بسته در پوشهٔ جدا و بدون assets یا frontend/public اجرا شد؛ import ماژول‌های جدید از خود artifact، **۱۵ منبع رسانه/فونت**، مجوز فونت، رندر زمین/نتیجه/دک/فروشگاه و تصویر قیمت ابیلیتی موفق بودند. تبدیل WebP استیکر نیز موفق بود؛ این بررسی محتوای ساختگی داشت و دادهٔ بازیکن را مصرف نکرد.
- Graphify به‌صورت AST-only به‌روز شد: **۳۸۶۴ گره، ۱۰۲۷۰ رابطه و ۲۴۴ community**؛ استخراج معنایی پولی اجرا نشد.
- اصلاح امتیاز نهایی تصویر Deck از انتشار قبلی در این نسخه حفظ شده است. مشکل مسدودکنندهٔ تازه‌ای در بررسی و تست‌های این مرحله مشاهده نشد؛ آزمون کلاینت واقعی تلگرام انجام نشده است.

## انتشار و حفظ داده‌ها

انتشار دستی مالک از حساب محدود telbattle-deploy، با host verification، همان کلید اصلی محافظت‌شده و receiver نصب‌شده انجام شد. قفل مشترک `/opt/telbattle/deploy.lock`، کنترل baseline و requirements، preflight آفلاین روی کپی SQLite و عدم تغییر منطقی دادهٔ startup اعمال شدند؛ سپس بکاپ سازگار، تعویض نسخه و شروع سرویس‌ها انجام شد.

رسید نهایی **status=ok** و **internal_health=ok** است؛ source_sha و run_id دقیقاً برابر جدول بالا و previous_sha همان runtime قبلی‌اند. کنترل داخلی شامل هر سه سرویس، خروج/ری‌استارت، API health، HTML پنل، API کارت/گزینه‌ها و HTML مینی‌اپ است.

schema migration، bootstrap، نصب dependency، restore دیتابیس، اعطای منابع تست یا تغییر flagهای اقتصاد اجرا نشد. موجودی بازیکنان و freeze جوایز حساب قدیمی حفظ شدند. دادهٔ جدید ورود اولیه/اعلان/شعار فقط هنگام عملیات واقعی بازی در namespace جدول‌های موجود ثبت می‌شود. rollback فقط کد را برمی‌گرداند و دادهٔ نوشته‌شده پس از شروع را خودکار restore نمی‌کند.

محدودیت تحویل اعلان: در قطع ناگهانی بین ارسال تلگرام و ثبت sent، پیام لول‌آپ ممکن است دوباره برسد؛ هیچ پاداشی از این مسیر دوباره پرداخت نمی‌شود. تحویل معمول، یک نمونهٔ ربات را فرض می‌کند.

# انتشار محدودیت بازی هم‌زمان و اصلاح انتخاب دک — ۱۷ اکتبر ۲۰۲۶

[PR شمارهٔ ۵](https://github.com/kasra-dastranj/telegram-card-game-bot/pull/5) پس از بازبینی کد، تست و CI توسط مالک تأیید و ادغام شد. سیستم محلی با `main` هماهنگ و artifact همان commit ادغام‌شده روی VPS منتشر شد. نسخهٔ قبلی، [انتشار نمایش خصوصی Quick](RELEASE_20261015_QUICK_PRIVATE_PRESENTATION.md) بود.

## رفتار منتشرشده

- ورود به بازی تازه برای هر دو شرکت‌کننده، در Quick، Deck، سه‌راندی مینی‌اپ، ASO، Easy، PvP قدیمی و Risk، زیر تراکنش SQLite با `BEGIN IMMEDIATE` بررسی می‌شود. درخواست‌های هم‌زمان از چند connection نمی‌توانند یک بازیکن را وارد دو بازی جدید کنند. پیام ربات روشن است و API با HTTP 409 و `active_match` پاسخ می‌دهد؛ رد ورود نباید منابع مصرف کند.
- پرچم دائمی busy یا schema قفل تازه اضافه نشد. بازی تمام‌شده/لغوشده، deadline، لابی معتبر Easy و انتقال درخواست Deck به نبرد واقعی لحاظ می‌شوند. دعوت معمولیِ waiting رزرو دائمی ایجاد نمی‌کند؛ پذیرش هر دو نفر را دوباره بررسی می‌کند. هم‌پوشانی‌های معتبر قبلی به زور قطع نمی‌شوند، ولی مانع ورود تازه‌اند.
- انتخاب دستی Quick پس از deadline رد می‌شود؛ skip خودکار ابیلیتی و اجرای تایمر Easy فرصت محدود ۱۲۰ثانیه‌ای دارند. درخواست/تایمر خیلی قدیمی نمی‌تواند بازی منقضی را از نو فعال کند یا منابع مصرف کند. زمان UTC و زمان محلی قدیمی جدا تفسیر می‌شوند.
- **سیاست بازی رهاشده:** ASO و Risk فاقد deadline مرحلهٔ پایدار، هنگام تلاش ورود بعدی پس از ۱۵ دقیقه **از زمان ساخت** بسته می‌شوند؛ این مدت از آخرین حرکت اندازه‌گیری نمی‌شود. ASO لغو و escrow ریسک دقیقاً یک بار بازپرداخت می‌شود؛ Raise بی‌پاسخ به پرداخت‌کنندهٔ آن و بقیهٔ pot به دو طرف برمی‌گردد. ledger موجود استفاده می‌شود؛ XP/Score یا پاداش برد تازه داده نمی‌شود. ابتدا escrow قدیمی بازیابی و سپس حداقل موجودی ورود Risk بررسی می‌شود. این رفتار جدیدِ زمان اجرای بازی است، نه restore دیتابیس یا اعطای ادمین.
- انتخاب Deck/Normal در پیوی دوست روی همان دعوت مشترک و به‌ترتیب نوبت است. در گروه، هر نفر منوی دک خودش را در پیوی ربات می‌گیرد و مستقل انتخاب می‌کند؛ پنل اضافی نوبتی ساخته نمی‌شود. کلیک تکراری، کاربر/دک غیرمجاز، مهلت و مسیر قدیمی کنترل شده‌اند. Random خودکار باقی است.
- تلاش پذیرش دعوت خود بازیکن با یکی از شش پاسخ محاوره‌ای رد می‌شود؛ اجازهٔ مسابقه با خود یا مصرف منابع نمی‌دهد.
- فرمول برد و پاداش عادی، عددهای اقتصاد، flagها، بستهٔ منابع تسترها، requirements و schema تغییر نکرده‌اند. migration، bootstrap، پاک‌سازی ادمین یا فعال‌سازی قابلیت خاموش انجام نشد.

## بررسی و نتیجه

- **اجرای کامل محلی: ۶۲۴ موفق / ۲ skipped** در Python 3.12، با SQLite موقت، bot mock و guard شبکه/مسیر دیتابیس؛ مدت واقعی ۷۶۳٫۴۰ ثانیه. checkout جدا و بدون config یا دیتابیس تولیدی استفاده شد. رقابت واقعی connectionها، حفظ منابع هنگام رد، deadline، Risk/ledger، انتخاب دک و مسیرهای API در تست‌ها پوشش دارند.
- CI نهایی main در **هر دو Python 3.11 و 3.9.25: تعداد ۶۲۵ موفق / ۱ skipped**؛ JUnitهای همان run دانلود و شمارها بررسی شدند. frontend build، syntax پنل، ساخت بسته و CI gate موفق‌اند.
- صحت manifest، hash و policy `no-change` برای **۱۰۰ فایل runtime** تأیید شد؛ هر **۹۶ فایل source** با blobهای canonical commit ادغام‌شده برابر بود و چهار فایل دیگر build همان CI هستند. Graphify بعد از دریافت کد به‌روز شد.
- انتشار دستی مالک از همان حساب محدود و receiver نصب‌شده، با کلید اصلی محافظت‌شده و host verification انجام شد. workflow تولید یا bootstrap جدید اجرا نشد و trusted helper یا مجوزهای سرور تغییر نکردند.
- receiver قفل مشترک `/opt/telbattle/deploy.lock`، requirements و preflight آفلاین روی کپی SQLite با عدم تغییر منطقی startup را کنترل کرد؛ سپس بکاپ سازگار، switch و شروع سرویس‌ها انجام شدند. migration یا restore داده اجرا نشد.
- receipt نهایی: `status=ok`، `operation=deploy`، `source_sha=8fc1b25cfd9f273a0cc305978b7bcc80ef917b3b`، `run_id=39003827324` و **`internal_health=ok`**. کنترل داخلی شامل هر سه سرویس، خروج صفر/بدون restart خودکار، API health، HTML پنل، API کاتالوگ/گزینه‌های کارت و HTML مینی‌اپ است.

DNS، TLS، nginx و تنظیم اتصال ربات تغییر نکردند.

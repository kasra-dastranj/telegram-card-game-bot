# انتشار پیام‌های جدید Quick — ۱۵ اکتبر ۲۰۲۶

تغییرات همکار در [PR شمارهٔ ۳](https://github.com/kasra-dastranj/telegram-card-game-bot/pull/3) بازبینی، تأیید و در `main` ادغام شدند. نسخهٔ محلی مالک با main هماهنگ و بستهٔ CI همان commit روی VPS منتشر شد.

## رفتار جدید

- متن شروع، انتخاب نوع، دعوت گروهی Normal/Random، پذیرش و انتخاب کارت Quick کوتاه‌تر و محاوره‌ای شده است. نام ربات از bot فعال خوانده می‌شود، نه مقدار ثابت تست/تولید.
- پیام برد عمومی فقط دیالوگ کارت برنده است؛ مدیای موجود و دکمهٔ «📋 مشاهده جزئیات» حفظ شده‌اند. مساوی و پایان مهلت پیام وضعیت کوتاه دارند.
- گزارش خصوصی شرکت‌کننده، برنده، زمین و قوانین آن، کارت‌ها، عددهای پایه و نهایی، جمع دو ویژگی، اثرهای اعمال‌شده، نام قابل فهم ابیلیتی و پاداش هر بازیکن را نمایش می‌دهد. غیرشرکت‌کننده به گزارش دسترسی ندارد.
- گزارش‌های قدیمی تک‌ویژگی، حالت مساوی/مهلت و نمایش Friendly آزموده شدند. Friendly و سایر flagهای خاموش فعال نشده‌اند؛ تغییر نمایشی، اجازهٔ فعال‌سازی نیست.
- قواعد محاسبه، settlement، مقدار پاداش، اقتصاد، موجودی، schema و وابستگی‌ها تغییر نکرده‌اند.

## کنترل و انتشار

- بررسی کد، پیام‌ها و تست‌های handler انجام شد. CI نهایی main در **هر دو Python 3.11 و 3.9.25، تعداد ۵۶۸ موفق / ۱ skipped** دارد؛ شمارها از JUnit همان run بررسی شدند. build، JavaScript پنل، بسته و CI gate موفق‌اند.
- اجرای کامل محلی روی checkout جدا و بدون config/دیتابیس تولیدی، با guard شبکه و SQLite موقت: **۵۶۷ موفق / ۲ skipped** در Python 3.12؛ مدت ۲۵۲٫۷۴ ثانیه. نصب وابستگی انجام نشد؛ محیط ناقص venv اولیه استفاده نشد.
- Graphify پس از دریافت کد به‌روز شد و نمادهای handler جدید در query دیده شدند.
- انتشار با درخواست صریح مالک، از مسیر موجود sender/protocol و receiver محدود انجام شد؛ اجرای workflow مستقل Deploy یا دورزدن تأیید Environment گزارش نمی‌شود. artifact فقط متعلق به CI موفق main بود، نه بستهٔ PR.
- نخستین اجرای client لینوکسی sender روی Windows، به مجوز فایل کلید موقت برخورد کرد و پیش از receipt/ارسال معتبر متوقف شد. اتصال با فایل اصلیِ محافظت‌شده و همان host verification، حساب محدود و پروتکل تأیید شد؛ هیچ مجوز کلید، helper سرور یا تنظیم امنیتی تضعیف نشد.
- receiver زیر `/opt/telbattle/deploy.lock`، صحت بسته، requirements و preflight آفلاین روی کپی SQLite با قرارداد `no-change` را کنترل کرد؛ سپس بکاپ سازگار، switch و راه‌اندازی سرویس‌ها انجام شد. migration یا restore دیتابیس اجرا نشد.
- receipt نهایی: `status=ok`، `operation=deploy`، `source_sha=6ae382537af51830f659182f76686e74f4ce3231`، `run_id=38714512165` و **`internal_health=ok`**. سلامت داخلی شامل هر سه سرویس، خروج صفر/بدون restart خودکار، API، HTML پنل، کاتالوگ/گزینه‌های کارت و Mini App است.
- بررسی بیرونی مستقل: Mini App روی دامنهٔ nip.io پاسخ **۲۰۰** داد. اولین probe دامنهٔ پنل خطای ارتباطی داشت؛ در بررسی مجدد، DNS به IP صحیح سرور رسید و درخواست بدون احراز هویت به `taraz.gwfarsi.ir/card-admin/` پاسخ مورد انتظار **۴۰۱** داد. هر دو مسیر بیرونی تأیید شدند؛ تغییری در شبکه، TLS یا احراز هویت انجام نشد.

دادهٔ بازیکن و secret در Git یا گزارش قرار نگرفت. بازی زنده/ارسال پیام تلگرام برای آزمون اجرا نشد. rollback احتمالی فقط کد را برمی‌گرداند و دیتابیس پس از شروع بازی را restore نمی‌کند. جزئیات پیام‌ها در [راهنمای Quick](../docs/QUICK_RESULT_MESSAGES_FA.md) است؛ تصمیم‌های اقتصاد و حساب‌های تستیِ انتشار قبلی حفظ می‌شوند.

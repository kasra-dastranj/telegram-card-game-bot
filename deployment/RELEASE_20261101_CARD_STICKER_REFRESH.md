# انتشار اصلاح تصاویر و استیکر فرم کارت — ۱ نوامبر ۲۰۲۶

[PR شمارهٔ ۱۵](https://github.com/kasra-dastranj/telegram-card-game-bot/pull/15) پس از بازبینی مالک و آزمون محلی ادغام شد. بستهٔ موفق CI شاخهٔ main روی VPS فعال است و کد محلی با GitHub هماهنگ شد. [نسخهٔ قبلی](RELEASE_20261025_ATTACK_MESSAGES_DETAILS.md) حفظ شده است.

## مشکل و رفتار اصلاح‌شده

فایل عکس یا استیکر در پنل عوض می‌شد، اما شناسهٔ فایل قبلی Telegram می‌توانست باقی بماند؛ پنل هم هنگام ذخیره یا تغییر فرم آن را دوباره می‌فرستاد. در نتیجه، تصویر صحنه تازه بود ولی استیکر مستقل کارت می‌توانست قدیمی باشد.

- آپلود عکس، شناسهٔ عکس و استیکر **همان فرم** را پاک می‌کند؛ آپلود استیکر فقط شناسهٔ استیکر همان فرم را پاک می‌کند. در فرم پایه، کش legacy متناظر هم پاک می‌شود؛ فرم‌های دیگر دست‌نخورده می‌مانند.
- جایگزینی روی همان نام فایل هم کش را منقضی می‌کند. شناسهٔ پایدار کارت همراه آپلود ارسال می‌شود تا ویرایش ذخیره‌نشدهٔ نام، پاک‌سازی را به کارت دیگری وصل نکند.
- پنل، شناسه‌های پاک‌شده را در draft نگه می‌دارد؛ جابه‌جایی بین Normal، Epic و Legend و ذخیرهٔ خانواده آن‌ها را برنمی‌گرداند.
- اگر مسیر تصویر هنگام ذخیره عوض شود، شناسه‌های عیناً تکرارشدهٔ قبلی حذف می‌شوند؛ شناسهٔ واقعاً جدید که مدیر صریحاً وارد کرده حفظ می‌شود.
- مسیر مشترک استیکر برد و ارتقا، پس از نبود شناسهٔ تلگرام، استیکر اختصاصی همان فرم و سپس تصویر کارت را بررسی می‌کند. مسیر نبرد هم از resolver مشترک استفاده می‌کند؛ استیکر مشترک قدیمی بر تصویر معتبر فرم مقدم نمی‌شود. فرم‌ها و کارت سفارشی از یکدیگر استیکر قرض نمی‌گیرند.
- اولویت آواتار انتخابی برد حفظ شده است. تلاش مجدد تحویل کارت اولیه هم با تست رگرسیون کنترل شد؛ fallback اضافه به استیکرهای legacy در مسیر پاداش وجود ندارد.

راهنمای استفاده و محدودیت‌ها: [اصلاح استیکر قدیمی](../docs/CARD_STICKER_REFRESH_FA.md).

## بررسی و آزمون

- **۱۹۲ تست مرتبط موفق** در ۱۱۵٫۵۹ ثانیه با Python 3.12 محلی: sticker refresh، card admin، card rewards، starter cards، Easy presentation، group attacks، victory voices و battle visuals. SQLite موقت و guard آفلاین فعال بودند.
- آزمون مرورگر واقعی با Edge headless، Flask، SQLite و پوشهٔ رسانهٔ جدا موفق بود: آپلود عکس و استیکر، ذخیره، تغییر فرم، جایگزینی روی همان مسیر، حفظ شناسهٔ Epic/Legend و نبود خطای JavaScript. تصویر خروجی نیز بررسی شد.
- بررسی syntax جاوااسکریپت پنل موفق بود. ایراد دیگری نیازمند تغییر تکمیلی مالک در این PR پیدا نشد؛ همان head بررسی‌شده ادغام شد.
- CI نهایی main برای Python 3.11 و 3.9.25، **هرکدام ۱۲۰۶ موفق، یک skipped و صفر failure/error** دارد. frontend build، JavaScript پنل، بسته‌بندی و CI gate موفق‌اند.
- hash همهٔ **۱۶۷ فایل runtime** بررسی شد؛ **۱۶۳ فایل source** با blob canonical همان commit برابر بودند و چهار فایل خروجی build هستند. آرشیو در پوشهٔ جدا استخراج و Python آن compile شد.
- Graphify با AST-only به **۴۴۸۹ گره، ۱۲۵۹۱ رابطه و ۲۷۲ community** به‌روز شد؛ API معنایی پولی اجرا نشد.

QA پیام واقعی به Telegram نفرستاد و محتوای تولیدی را ویرایش نکرد. آزمون واقعی ارسال کارت در حساب بازیکن ادعا نمی‌شود.

## سلامت و اقدام برای آپلودهای قبلی

رسید انتشار **status=ok / internal_health=ok** است. SHA ثبت‌شده و مقصد current درست‌اند؛ هر سه سرویس telbattle-bot، telbattle-api و telbattle-admin فعال‌اند و ExecMainStatus=0 و NRestarts=0 دارند. health، API کاتالوگ و گزینه‌های پنل، صفحهٔ مدیریت و Mini App در داخل سرور موفق‌اند. HTML پنلِ درحال سرو، HTML Mini App و سه فایل JS/CSS مینی‌اپ با manifest بسته hash یکسان دارند.

بررسی بیرونی پس از انتشار از محیط فعلی: صفحهٔ پنل، API کارت‌ها و صفحه‌های زمین، حمله، کارت سفارشی، ویس، Rare و ایستراگ با BasicAuth همگی **۲۰۰**؛ پنل بدون ورود **۴۰۱** و API ویس بدون توکن داخلی **۴۰۳**؛ Mini App عمومی **۲۰۰**. خطای موقت اتصال دو درخواست اولیه پیش از انتشار در تکرار رفع شد. resolver محلی دو نام را به آدرس‌های واسط 198.18.x.x می‌برد؛ این نتیجه آزمون دسترسی از محیط فعلی است و اتصال مستقیم بدون VPN همهٔ شبکه‌ها را اثبات نمی‌کند. DNS/TLS/nginx تغییری نکردند.

این اصلاح پاک‌سازی عمومی کش‌های قدیمی انجام نمی‌دهد. برای کارتی که **پیش از انتشار** تصویرش عوض شده و هنوز استیکر قبلی را نشان می‌دهد، پنل را تازه کنید، همان کارت و فرم را انتخاب کنید و استیکر دلخواه را یک‌بار دوباره آپلود و ذخیره کنید؛ مثال مطرح‌شده در PR، Heisenberg Normal است. عکس کارت، استیکر اختصاصی و آواتار برد فایل‌های مستقل‌اند. در این انتشار هیچ‌یک بدون انتخاب مدیر جایگزین نشد.

commit مستندسازی بعدی runtime را تغییر نمی‌دهد. اسرار و اطلاعات بازیکنان وارد Git نشده‌اند.
